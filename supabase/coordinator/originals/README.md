# Registro privado de originales (#103)

Implementa el contrato registry.reserve/markVerified del adaptador #109. Reserva persistente por libraryId y SHA-256, carpeta dedicada autorizada, fileId globalmente único, tamaño inmutable; una confirmación posterior al readback acredita la versión observada, nunca cambia una reserva o reemplaza automáticamente un original. Todas las mutaciones verifican la pertenencia del dispositivo y comparten el bloqueo de biblioteca existente. Rol NOLOGIN separado bia_originals_caller, sin SELECT ni acceso a core, solo las dos funciones privadas; no conceder a gateway HTTP general, anon, authenticated ni service_role. Solo un trabajador de almacenamiento de confianza que haya realizado verificación de bytes puede invocar verify_original; nunca convertirlo en acción accesible directamente por Android. No equivale a prueba física Drive; el rol no tiene login, secreto ni servicio configurados. La autorización de la carpeta exige consentimiento de servidor, aún pendiente. No se toca ningún libro ni archivo real.

El futuro puerto JS del trabajador ejecutará cada reserva en transacción que concluya antes de permitir la subida y verify tras comprobar SHA/tamaño/version. La carpeta se obtiene de configuración administrativa autorizada, no de parámetros de Android. El snapshot de backup debe usar exclusivamente filas verificadas y comprobar de nuevo contenido y versión. No eliminar originales locales por una respuesta de reserva. Tests de PostgreSQL efímero: dos dispositivos misma identidad, reintento, colisión de tamaño/ID, carpeta/token ajeno y CAS de confirmación. Se reutiliza CI SQL existente; añadir prueba física concurrente del registro y adaptador antes de activar.
