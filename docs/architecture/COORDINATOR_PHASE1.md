# Coordinador privado — fase 1 (25/11/2026)
El propietario confirma servicio externo sin registro en BibliotecaAI. Se reutiliza el proyecto Supabase BibliotecaIA, no se reactiva el antiguo SyncEngine ni auth.users. ADR-008 conserva prohibición de OAuth y API Drive en cliente. Autorización nueva limitada a coordinación.

## Fase 1
Esquema aislado bia_coord, sin acceso de anon/authenticated/service_role, RLS activado, sin API pública. apply_change es una primitiva transaccional de servidor: CAS por entidad, revisión global, recibos idempotentes y lápidas. Cambios de entidades distintas no se sobrescriben, conflicto de la misma entidad se devuelve al cliente y debe conservar ambos cambios en su cola/versiones. Identidad de libro por hash, NO confirma un original físico; reserva/verificación y acceso de libros aún pendientes. No se transfiere información real ni se cambia ningún dispositivo. Test SQL sintético con rollback. El registro de operaciones no se purga sin protocolo de acknowledgement.

## Fases siguientes (bloqueantes antes de activar Android)
- Gateway TLS con credencial aleatoria por instalación, emparejamiento de un solo uso y revocable; secreto en Android Keystore, hash del token en servidor, autorización por biblioteca y dispositivo. No email, OAuth, cuenta ni credenciales IA. Rate limit, aislamiento, pruebas de acceso cruzado y reintentos. El backend recibe únicamente metadatos necesarios, que pueden ser privados; informar antes de migrar.
- Cola local duradera y pull por revisión; mapeo de todos los datos Room, conflictos explícitos (notas/versiones), posición efectiva y bajas. Bloquear cambios si no hay confirmación; no purgar operaciones ante errores. Mismo libraryId en todos los dispositivos.
- Originales y ZIP: SAF permite acceso por URI concedido en cada dispositivo, no concede al servidor ni al resto de instalaciones acceso automático a ese documento. Para conservar Drive como depósito único, se necesita o bien acceso autorizado del backend a Drive con credenciales de almacenamiento administradas por propietario, o un dispositivo escritor fijo con permisos y mecanismo de entrega seguro; el segundo no garantiza disponibilidad si está desconectado. No simular acceso mediante URI de otro dispositivo. No activar otra nube de originales ni OAuth sin decisión explícita. Un solo estado autoritativo en Postgres; Biblioteca.json en Drive, si se materializa, es una proyección de solo escritura del coordinador, nunca otra fuente de verdad.
- Importar y reservar hash único transaccionalmente; verificar bytes antes de confirmar, descarga por hash; conservar local ante error. Copia ZIP por único escritor, incluir todo, restauración verificada. Migración inventario/backup/ensayo/corte de todos los dispositivos; conservar carpeta vieja en solo lectura. No borrar archivos.
- CI con PostgreSQL y pruebas simultáneas reales, dispositivo offline, conflictos, restauración y Drive físico. El test actual verifica semántica secuencial de CAS/idempotencia, no prueba concurrencia física.
