# Persistencia de identidad del coordinador (#103)

Incremento aislado de Android, sin endpoint ni activación. El futuro asistente usa CoordinatorEnrollment(AndroidCredentialVault(context)) fuera del hilo UI. beginCreate exige código de alta autorizado de 256 bits; beginJoin exige libraryId existente y código de vinculación. Ambos generan y persisten IDs/token una sola vez antes de red. Reintentos con la misma identidad y código; si ya existe otro flujo o identidad activa, se bloquea. confirmMembership solo después de que #106 valide IDs de la respuesta autenticada; elimina código del registro activo. La emisión/consumo de código de alta por servidor aún no existe: no invocar create sin ese contrato. No hay reset implícito, revocación ni recuperación de clave perdidas: futura UI debe explicar el bloqueo y obtener autorización de recuperación.

Vault AES-256-GCM en AndroidKeyStore, IV generado por cipher, AAD fijo versionado, archivo cifrado y atómico en noBackupFilesDir. Lectura/verificación tras cada escritura. Nunca registrar códigos, token o payload, ni guardar en ZIP, Room o Drive. AndroidManifest existente allowBackup=false; además el fichero queda fuera de backup automático por ubicación. No se altera el código de backup. Si archivo/clave faltan de forma discordante, falla cerrado, nunca crea otro dispositivo. Si se pierde identidad por borrado íntegro de datos/desinstalación, tratar la nueva instalación como vinculación explícita, nunca crear biblioteca automáticamente. No asumir recuperación automática ni exclusión multiplataforma: sincronización local del manager en proceso Android principal.

Integración prevista: mapear StoredEnrollment a CoordinatorIdentity.restore de #106, enviar approvalCode únicamente al gateway de alta, código de join al endpoint de vínculo, confirmar solo tras validación. El agente 2 diseña UX sin persistir secretos propios. Tests JVM con vault doble: reinicio lógico, idempotencia, join, conflictos, corrupción y fallo de persistencia. Falta prueba instrumental AndroidKeyStore/AtomicFile (incluido fallo real) y A/B con gateway, sin datos reales. No publicar como biblioteca única operativa.
